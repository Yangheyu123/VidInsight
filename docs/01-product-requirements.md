# VidInsight 产品需求文档（PRD）

> 版本：v1.0
>
> 状态：开发基线
>
> 产品定位：AI 驱动的短视频数据智能分析平台

## 1. 背景与目标

短视频运营团队往往需要在多个抖音账号后台之间切换，数据分散、指标口径不一，内容表现与创作特征之间也缺少可解释的关联。VidInsight 将已授权账号的数据集中采集、标准化和分析，使运营人员能快速回答：

- 账号和视频当前表现如何，变化发生在哪里；
- 哪些主题、开场、场景和发布时间表现更好；
- 评论体现了怎样的情绪、意图和风险；
- 下一轮内容可以保留、调整或尝试什么。

### 1.1 成功目标

| 目标 | MVP 成功标准 |
|---|---|
| 多账号统一监控 | 稳定绑定并监控至少 10 个已授权账号 |
| 数据及时可靠 | 新视频发现不超过 15 分钟；24 小时采集成功率不低于 99% |
| 快速理解表现 | 总览、账号详情、视频列表 P95 查询小于 3 秒 |
| 数据可解释 | 每个指标显示口径、更新时间和来源；估算值显示置信区间 |
| 提升运营效率 | 运营人员无需切换平台后台即可完成日常复盘 |

### 1.2 非目标

- 不建设绕过签名、验证码、访问控制或反自动化机制的爬虫平台。
- 不提供刷量、自动点赞、自动评论、自动发布等平台操控能力。
- MVP 不承诺逐用户播放进度；该数据只有自有播放器埋点才能准确提供。
- MVP 不建设通用 BI、自训练大模型或复杂推荐系统。
- 不在没有版权与明确授权时长期保存视频源文件。

“不建设绕过机制的爬虫平台”不等于完全排除页面采集：当官方 API、受控 Computer Use 和授权导入/合作数据均无法提供验收必需字段时，可以启用字段级受控爬虫，但必须满足账号授权、访问政策、合规审批、低频只读、无技术规避和可立即熔断等条件。

## 2. 用户与权限

| 角色 | 典型任务 | 权限 |
|---|---|---|
| 管理员 `admin` | 管理成员、账号、数据源和系统设置 | 工作区全部权限 |
| 运营 `operator` | 查看数据、导入数据、触发分析、维护标签 | 业务读写，不可管理成员和密钥 |
| 访客 `viewer` | 查看和导出被授权的数据 | 只读 |

系统按工作区 `workspace` 隔离数据。即便 MVP 只有一个团队，所有核心表和查询也必须带工作区边界，防止后续多租户改造产生数据泄露。

## 3. 核心业务流程

### 3.1 账号接入

1. 管理员点击“连接抖音账号”。
2. 系统生成带 `state` 的官方 OAuth 授权链接。
3. 用户在抖音官方页面完成授权。
4. 后端校验回调、交换 Token，并加密保存凭证。
5. 系统创建首次全量同步任务，完成后展示账号与视频数据。
6. Token 即将到期时自动刷新；刷新失败则提示重新授权。

### 3.2 日常采集

1. 调度器根据账号、视频年龄、优先级和 API 压力生成任务。
2. Worker 获取新视频、指标快照和评论游标增量。
3. 原始响应短期归档，标准化数据幂等写入 PostgreSQL。
4. 采集成功后刷新聚合数据，并按条件触发 AI 分析。
5. 失败任务指数退避；鉴权、配额或验证码问题进入人工处理。

### 3.3 视频分析

1. 运营选择单个或批量视频发起分析。
2. 系统确认分析权限、内容可访问性和成本预算。
3. 任务依次完成元数据、ASR、OCR、关键帧、评论与 LLM 综合分析。
4. 每个步骤单独记录状态，允许失败重试和部分结果展示。
5. 报告展示模型版本、生成时间、证据和置信度。

### 3.4 数据导入

1. 运营下载模板或上传 CSV/XLSX。
2. 系统仅做预检，不直接写正式表。
3. 页面展示字段映射、错误行和覆盖范围。
4. 用户确认后创建导入任务；幂等写入并生成审计记录。
5. 错误行提供可下载报告。

### 3.5 缺失字段兜底

1. 产品为每个必需字段登记名称、业务目的、账号范围、刷新要求和可接受质量等级。
2. 后端依次验证官方 API、受控 Computer Use、用户导入和合同数据是否可获得。
3. 前述来源均不可用时，管理员可提交字段级受控爬虫申请，明确域名、路径、字段、频率、授权与审批到期时间。
4. 受控爬虫先执行单页 dry-run，解析结果进入 staging；通过 schema 校验和人工抽样对账后才进入正式指标快照。
5. 遇到验证码、挑战页、403/429、页面指纹变化或字段异常立即熔断，不尝试破解或规避。
6. 页面和导出始终展示 `source`、`quality` 与最近校验时间；来源切换产生审计记录。

## 4. 功能范围

### 4.1 P0：MVP 必须交付

| 模块 | 用户故事 | 核心要求 |
|---|---|---|
| 登录与工作区 | 作为成员，我只能进入被授权的工作区 | 登录、退出、角色鉴权、数据隔离 |
| 总览 | 作为运营，我想一眼判断整体表现 | 账号数、视频数、播放、点赞、互动率、趋势、Top 视频、数据新鲜度 |
| 账号管理 | 作为管理员，我想批量维护矩阵账号 | 批量录入、新增、删除、启用/停用、OAuth、授权状态、Token 到期提示、手动同步 |
| 账号详情 | 作为运营，我想复盘单账号趋势 | 账号摘要、趋势、增量、热门视频、同步记录 |
| 视频列表 | 作为运营，我想搜索、筛选和排序全部视频 | 账号/时间/状态筛选，分页，指标排序，批量分析 |
| 视频详情 | 作为运营，我想查看视频生命周期与分析结果 | 最新指标、历史曲线、元数据、评论摘要、分析状态 |
| 采集任务 | 作为管理员，我想知道数据为何没有更新 | 状态、来源、时间、耗时、错误、重试、暂停 |
| 数据源连接器 | 作为管理员，我想在官方字段缺失时采用受控兜底 | 来源优先级、字段白名单、dry-run、审批、抽检、熔断与审计 |
| 导入 | 作为运营，我想补充后台导出数据 | 模板、预检、确认、结果报告、审计 |
| 系统状态 | 作为管理员，我想查看关键数据是否新鲜 | 最近同步、失败任务、授权异常、简要健康状态 |
| 周期报表与导出 | 作为运营，我想按日/周/月复盘并交付报表 | 周期切换、账号/时间筛选、指标排序、视频明细、XLSX 导出和历史回溯 |

### 4.2 P1：内容洞察

| 模块 | 能力 |
|---|---|
| 内容分析 | 主题、标签、情绪、场景、人物、前三秒钩子、ASR、OCR |
| 评论洞察 | 情感分布、意图、高频主题、典型评论、风险提示 |
| 爆款分析 | 爆款评分、特征贡献、相似优质内容、改进建议 |
| 对比分析 | 多账号、多视频、多个时间区间横向对比 |
| 报告导出 | 导出当前筛选条件下的 XLSX/CSV 与可分享报告 |

### 4.3 P2：规模化与智能运营

- 用户画像和偏好建模；
- 自动选题、脚本建议和内容实验管理；
- 预测分析与异常检测；
- 50-100 账号的分析库与任务水平扩展；
- 更细粒度 RBAC、SSO 与审批流。

全局顶栏提供工作区切换、时间范围、数据更新时间、搜索和用户菜单。页面级筛选条件应同步到 URL，便于刷新、分享和返回。

## 6. 指标口径

| 指标 | 公式或定义 | 来源 |
|---|---|---|
| 周期播放增量 | 每个视频“周期结束最后快照 - 周期开始前最后快照”之和 | 官方 API/可靠来源快照 |
| 周期点赞增量 | 每个视频周期点赞增量之和 | 官方 API/可靠来源快照 |
| 周期评论/分享/转发增量 | 对应累计指标在周期内的快照差值之和 | 官方 API/可靠来源快照 |
| 平均播放量 | 总播放量 / 视频数；视频数为 0 时显示 `—` | 计算值 |
| 互动量 | 点赞 + 评论 + 分享 | 计算值 |
| 互动率 | 互动量 / 播放量；播放量为 0 时显示 `—` | 计算值 |
| 粉丝增长 | 期末粉丝数 - 期初粉丝数 | 官方 API 日指标 |
| 爆款率 | 达到工作区爆款规则的视频数 / 已发布视频数 | 计算值 |
| 完播率 | 完整观看会话 / 有效播放会话 | 官方聚合或自有埋点 |
| 估算完播率 | 模型预测值，必须同时展示置信区间 | 模型估算 |
| 数据新鲜度 | 当前时间 - 最近成功采集时间 | 系统计算 |

所有增长率默认与上一个等长周期比较。缺失数据不得填 0；使用 `null` 并在界面显示“暂无数据”。快照计数是累计值，相邻快照差值小于 0 时标记异常，不直接计入增长。

日按 `Asia/Shanghai` 自然日，周从周一开始，月按自然月；API 使用左闭右开区间 `[start_at, end_at)`。若缺少期初基线，使用周期内最早与最晚可靠快照计算并标记 `partial_baseline=true`。平均完播率优先按样本数加权；无样本数时只可显示简单平均并标注口径。

### 6.1 MVP 智能诊断规则

诊断先由确定性规则产生结构化结论，LLM 仅可润色建议；LLM 失败时保留规则模板。默认使用同账号近 30 天且不少于 10 条视频的生命周期对齐分位数，样本不足时使用矩阵基线或版本化绝对阈值。

| 规则码 | 触发条件 | 必须输出的参考方向 |
|---|---|---|
| `LOW_COMPLETION` | 可靠完播率低于 P30/配置阈值 | 开头钩子、视频节奏待优化 |
| `HIGH_PLAY_LOW_ENGAGEMENT` | 播放 ≥ P70 且互动率 < P30 | 缺少互动设计，检查提问和评论引导 |
| `LOW_PLAY_HIGH_COMPLETION` | 播放 < P30 且完播率 ≥ P70 | 封面标题或选题曝光不足 |
| `LOW_PLAY_LOW_COMPLETION` | 播放与完播率均 < P30 | 选题脚本可能不匹配受众 |
| `HIGH_PLAY_LOW_FOLLOW` | 播放 ≥ P70 且可靠视频级涨粉转化 < P30 | 人设、系列价值和关注引导不足 |

完播率或视频级涨粉归因不可用时，不得靠猜测触发依赖该字段的确定性规则；显示“数据不足”和缺失来源。每条建议展示证据、阈值版本、来源、质量、生成时间和“仅供运营参考”的声明。

## 7. 状态模型

### 7.1 账号授权状态

`pending → active → expiring → expired`，也可能进入 `revoked` 或 `error`。解绑后状态为 `revoked`，立即停止新任务，但按保留策略处理历史数据。

### 7.2 任务状态

`queued → running → succeeded`；异常时进入 `retrying → failed`；人工或系统可进入 `paused` / `cancelled`。状态变化必须记录时间、操作者、错误码和关联任务。

### 7.3 AI 分析状态

`not_started → queued → processing → completed`，可进入 `partial` 或 `failed`。部分成功时必须展示已完成步骤和缺失原因。

## 8. 关键交互规则

- 首次进入无数据页面时，主行动按钮是“连接账号”，而不是展示空白图表。
- 解绑账号、取消任务、删除导入数据等操作需要说明影响并二次确认。
- 触发同步或分析后立即返回任务 ID；界面通过轮询展示进度，不长时间阻塞请求。
- 表格默认服务端分页；分页大小为 20、50、100，最大 100。
- 时间范围默认最近 7 天，可选 24 小时、30 天、90 天和自定义。
- 数据导出沿用当前筛选，超过同步导出阈值时转异步任务。
- 数值使用紧凑格式（如 `12.8 万`），悬停显示精确值与口径。

## 9. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 常用查询 P95 < 3 秒；普通 API P95 < 500ms（不含外部 API 与异步任务） |
| 可用性 | MVP 月可用性目标 99.5%；生产阶段 99.9% |
| 可扩展性 | 10 账号起步，架构支持扩展至 100 账号；Worker 可水平扩容 |
| 安全 | TLS、密钥加密、最小权限、审计日志、工作区隔离 |
| 可访问性 | 关键流程达到 WCAG 2.1 AA；完整键盘操作；非颜色唯一编码 |
| 兼容性 | 最近两个稳定版 Chrome、Edge、Safari；桌面优先，最小宽度 1024px |
| 可观测性 | 请求、任务、账号和数据源均有可关联的 trace/request ID |
| 可恢复性 | 生产目标 RPO ≤ 15 分钟、RTO ≤ 2 小时 |

## 10. MVP 业务验收

MVP 上线必须同时满足：

1. 管理员能通过官方 OAuth 绑定、刷新和解绑账号。
2. 10 个账号连续运行 7 天，采集成功率不低于 99%，无重复主数据。
3. 新视频最迟 15 分钟出现，指标快照和趋势口径一致。
4. 总览、账号详情、视频列表和视频详情在目标数据量下 P95 小于 3 秒。
5. 所有深度数据明确显示官方、导入、自有埋点或模型估算来源。
6. 401/403、429、Token 过期和外部服务超时均可观察、告警和恢复。
7. 工作区隔离、角色权限、凭证加密、审计日志通过安全验收。
8. 备份恢复演练成功，并证明达到约定 RPO/RTO。
9. 启用的 Computer Use/受控爬虫连接器均有有效审批和字段白名单；挑战页、结构漂移与异常值测试可停止正式写入。
10. 账号可批量录入并完成新增、删除、启用/停用；停用账号不再产生采集任务。
11. 日/周/月切换、账号与时间筛选、指标排序、周期汇总和视频明细结果一致。
12. XLSX 至少包含“汇总、视频明细、口径说明”三个工作表，并继承当前筛选条件。
13. 五类智能诊断规则使用固定样本逐项命中；缺少完播率/涨粉归因时正确显示数据不足。

## 11. 依赖与待决策

- 开放平台应用审批和实际配额是首要外部依赖。
- Computer Use 与受控爬虫必须在法务、安全和账号主体授权确认后按连接器单独启用；扩大账号、域名、字段或频率视为新审批。
- AI 服务商、模型版本、单任务预算和数据出境方案需在 P1 前确认。
- 爆款规则初始可用“播放量 ≥ 10 万”，但应实现为工作区可配置规则，不写死在代码中。
