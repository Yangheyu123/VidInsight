# VidInsight 实施计划

## 1. 交付策略

以纵向业务链路而非技术层横向铺开：先让一个授权账号从官方 API 进入数据库并出现在真实看板，再扩到多账号、稳定性和 AI。计划按 13 周、约 2.5-3 人 MVP 团队估算，可按实际审批进度调整。

## 2. 里程碑

| 阶段 | 周期 | 目标 | 可验收交付物 |
|---|---:|---|---|
| M0 启动与风控 | W1 | 明确合法数据边界和开发基线 | Scope 清单、权限矩阵、威胁模型、UI tokens、环境骨架 |
| M1 首条链路 | W2-W3 | 单账号授权并展示真实视频数据 | OAuth、账号/视频/快照表、首次同步、简版总览 |
| M2 多账号 MVP | W4-W6 | 10 账号稳定采集与核心看板 | 调度、重试、对账、账号/视频页面、任务页、监控 |
| M3 内容洞察 | W7-W9 | 评论和视频分析形成可解释结果 | 评论洞察、ASR/OCR/关键帧、分析版本与证据 |
| M4 智能分析 | W10-W11 | 爆款归因和运营建议 | 评分、归因、建议、批量分析、成本控制 |
| M5 生产化 | W12-W13 | 安全、性能与恢复达到上线门槛 | RBAC、审计、压测、备份恢复、灰度与验收报告 |

## 3. 工作分解

### M0：启动与风控

- 确认开放平台应用、Scope、配额、回调域名和测试账号。
- 法务确认官方 API、用户导入、评论处理和模型调用边界。
- 初始化前后端、Compose、CI、代码质量与环境配置。
- 落地 Design Token、App Shell 和 OpenAPI 错误模型。
- 建立 workspace/user/member、审计与密钥管理基础。

退出标准：代码骨架可启动，空库迁移成功，登录与工作区隔离有自动测试；未确认的数据源不进入开发。

### M1：首条链路

- OAuth state、回调、Token 加密、刷新和授权状态。
- account、video、video_metrics_snapshot、collection_job 与 checkpoint。
- Douyin adapter、首次同步、幂等写入和基础错误映射。
- 总览核心指标、视频列表、数据来源与更新时间。

退出标准：一个测试账号真实授权后可自动出现视频与指标，重复同步无重复数据。

### M2：多账号 MVP

- Celery Beat 冷热调度、账号级锁、限流和重试。
- 账号列表/详情、视频详情/趋势、任务中心和手动同步。
- 导入预检与提交、数据质量规则、每日对账；确认所有验收字段的数据源矩阵。
- 对 API/Computer Use/导入仍缺失的必需字段，仅在审批完成后实现受控爬虫 Policy Gate、dry-run、staging/quarantine 与 Kill Switch。
- 日志、指标、告警、失败人工处理与 Kill Switch。
- 10 账号连续运行与性能优化。

退出标准：PRD 中采集、查询与基础安全验收通过，可供运营日常复盘。

### M3：内容洞察

- 评论增量采集、去标识化、保留与删除任务。
- 分析运行/步骤模型和独立 analysis queue。
- ASR、OCR、关键帧、主题/情绪/意图的适配器与结构化输出。
- 视频分析和评论洞察页面，显示证据、置信度、来源和版本。

退出标准：分析可部分成功、重试、取消；结果能追溯到输入、模型和证据。

### M4：智能分析

- 爆款规则配置、基线与特征归因。
- LLM 综合报告和运营建议，输出 schema 校验。
- 批量分析、预算、配额、成本统计和敏感内容过滤。
- 对比分析与报告导出。

退出标准：建议可解释，不伪造平台数据；超预算和模型故障可控。

### M5：生产化

- RBAC、审计查询、安全扫描和渗透测试修复。
- 目标数据集压测、索引/物化视图优化。
- 备份、PITR、恢复演练和应急 Runbook 演练。
- staging 72 小时稳定性、生产灰度和上线复盘。

退出标准：测试文档中的发布验收全部签字通过。

## 4. 团队建议

| 角色 | MVP 投入 | 主要职责 |
|---|---:|---|
| 后端/数据工程师 | 1-2 | API、采集、数据模型、任务与运维 |
| 前端工程师 | 0.5-1 | Design System、看板、状态与联调 |
| 算法/数据分析 | 0.5-1 | 分析流水线、指标与评估 |
| 产品/运营/合规 | 0.3-0.5 | Scope、口径、验收和授权 |
| DevOps/安全 | 0.2-0.5 | CI/CD、监控、秘密、恢复与评审 |

一个人承担多个角色时仍需保留安全、迁移和验收的复核机制。

## 4.1 排期与成本确认

本期以 13 周、2.5–3 人团队为基线。W1 必须确认抖音 Scope、六项必需字段的可用来源、配额、调用频率和首批 10 个授权账号；任何一个必需字段没有获批且可验证的 API/Computer Use/导入/受控爬虫链路时，不进入 MVP 验收。

| 阶段 | 账号规模 | 基础云资源与运行成本（不含人力/数据采购） | 额外成本因素 |
|---|---:|---:|---|
| 本地研发 | 0–10 | 使用现有 8 核、32 GB 开发机时接近 0 | 测试账号、模型调用 |
| MVP 内测 | 10–20 | ¥1,500–5,000/月 | 抖音合作数据、LLM、备份、人工处理 Computer Use/爬虫异常 |
| 内部生产 | 50–100 | ¥8,000–30,000/月 | Worker 扩容、存储、模型、合规审核与页面解析维护 |

上述为容量规划估算；上线前用真实配额、视频量、评论量、刷新频率和连接器人工维护工时重新核算。

## 5. 优先级与取舍

当时间不足时，按以下顺序保护范围：

1. 授权、数据正确性、工作区隔离与审计；
2. 采集稳定性、数据新鲜度与故障可见性；
3. 总览、账号和视频核心看板；
4. 导入与评论；
5. AI 分析深度与视觉增强；
6. Computer Use、受控爬虫、预测与高级推荐；其中受控爬虫只在必需字段确实缺失且审批通过时建设。

不通过牺牲来源标注、权限或幂等性来赶进度。

## 6. 风险登记

| 风险 | 可能性/影响 | 预防与应对 |
|---|---|---|
| Scope 审批不全 | 高/高 | W1 申请；缺失指标显示不支持；用授权导入补充 |
| 平台配额与接口变化 | 中/高 | adapter 隔离、schema fixture、限流、降级与对账 |
| Computer Use 风控 | 中/高 | 默认关闭、法务批准、只读低频、验证码即停 |
| 受控爬虫合规与账号风险 | 中/高 | 字段级审批、Policy Gate、固定出口、无规避、Kill Switch |
| 页面结构漂移 | 高/中 | schema 指纹、fixture、quarantine、人工抽检、自动熔断 |
| 指标口径争议 | 中/高 | 数据字典、来源、版本、样例和产品签字 |
| AI 成本/质量不可控 | 中/中 | 预算、分步缓存、结构校验、评估集和可解释证据 |
| 多存储过度设计 | 中/中 | MVP 仅 PG，达到量化门槛再扩展 |
| 敏感数据泄漏 | 低/极高 | 最小化、加密、HMAC、审计、DLP 和应急开关 |
| 小团队关键人风险 | 中/中 | Runbook、代码审查、自动化和轮值文档 |

## 7. 项目管理规则

- 每个里程碑有 Demo、指标与退出标准，不以“代码写完”代替验收。
- 每周复盘数据源审批、范围、风险、错误预算和成本。
- 需求条目必须包含角色、价值、验收、权限、数据来源和异常状态。
- 新技术或服务引入需说明触发证据、成本、运维影响和退出方案。
- 生产问题形成可跟踪改进行动，严重问题完成无责复盘。
