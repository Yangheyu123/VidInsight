# PRD:爆款雷达 ViralRadar — 短视频爆款采集与自动分析工具

| 项 | 内容 |
|---|---|
| 版本 | V1.0(待评审) |
| 日期 | 2026-10-26 |
| 赛道定位 | 青年思辨哲学短视频,受众 18–23 岁男性,核心 KPI:高收藏率 |
| 技术底座 | Python + yt-dlp(元数据采集,不下载视频) |
| 状态 | ⏸ 等待需求方核对,核对通过后进入开发 |

---

## 1. 背景与目标

### 1.1 背景
个人创作者在哲学思辨赛道做短视频,需要把"爆款感觉"变成"可复制的范式":目前判断选题、标题、发布时间全凭经验,缺少数据支撑。

### 1.2 核心目标
用 yt-dlp 把 B站 / YouTube 上对标账号与赛道关键词的视频**元数据**批量采集下来,自动统计出爆款规律(时段/标题/时长/互动率),再调用大模型生成**结构化爆款拆解报告**,直接产出可模仿的标题模板、钩子、脚本节奏。

### 1.3 使用者
本人(个人创作者),命令行操作,单机 Windows 环境。

---

## 2. 使用场景

| 场景 | 操作 | 产出 |
|---|---|---|
| S1 对标账号扫描 | 给一个 B站空间 / YouTube 频道地址,抓取历史视频 | 全量元数据 CSV + 爆款子集 + 拆解报告 |
| S2 赛道关键词扫描 | 输入关键词(如"哲学思辨""人生意义"),扫 B站/YouTube 搜索结果前 N 条 | 同上 |
| S3 数据复盘 | 对已采集的 CSV 重新统计/重新生成报告(改爆款倍数、换模型) | 新统计报告,无需重新采集 |

## 3. 范围界定

### 3.1 V1.0 范围内(In Scope)
- 平台:**B站、YouTube**(经 yt-dlp 引擎)
- 两种采集模式:①对标账号全量 ②关键词搜索
- 只抓元数据,**绝不下载视频内容**
- 统计分析 + LLM 拆解报告(CLI 运行,输出 CSV + Markdown)

### 3.2 明确不做(Out of Scope)
- ❌ 视频文件/音频/字幕下载
- ❌ 抖音平台采集(yt-dlp 对抖音支持弱且风控严,见 3.3)
- ❌ GUI / 网页界面
- ❌ 评论内容抓取(V1 不做,列为 V1.2 候选)

### 3.3 抖音相关需求的承接方式(重要边界说明)
你提到的三类抖音需求,数据来源不同,承接方案如下:

| 需求 | 数据事实 | 承接方案 |
|---|---|---|
| 抖音对标账号采集 | 2s/5s 跳出率、完播率属**创作者私有后台数据**,外部工具拿不到别人账号的这些数据 | 用本工具扫 B站/YouTube 同赛道账号替代(公开数据充分);抖音对标靠人工刷 + 巨量算数 |
| **个人账号**作品 2s/5s、完播率、收藏率 | 只能从**抖音创作者中心后台导出**(Excel) | **V1.1**:给 analyzer 加列名映射,直接吃后台导出的表格,同一套统计/报告引擎复用 |
| 个人矩阵账号管理 | 多账号监控是持续性需求 | **V2.0**:Windows 任务计划定时跑各账号采集任务 + 汇总看板 |

## 4. 总体架构

### 4.1 架构图

```
┌───────────────────────── CLI 入口层 main.py ─────────────────────────┐
│    collect(采集)      analyze(统计)      report(AI 拆解报告)          │
└────────┬────────────────────┬──────────────────────┬────────────────┘
         ▼                    ▼                      ▼
┌──────────────────┐  ┌───────────────┐  ┌─────────────────────┐
│ M1 采集 collector │→ │ 数据层 CSV    │→ │ M3 统计 analyzer     │
│ yt-dlp 引擎       │  │ output/raw/   │  │ pandas + jieba      │
│ 两阶段采集+限流   │  │ utf-8-sig     │  │ 爆款判定/时段/标题   │
└───────┬──────────┘  └───────────────┘  └─────────┬───────────┘
        │                                    stats.md / viral.csv
        ▼                                          ▼
  B站 / YouTube                            ┌─────────────────────┐
  (代理 / cookies 可选)                    │ M4 报告 report       │
  api.bilibili.com                         │ LLM API(OpenAI 兼容)│
  (仅补抓收藏数)                            │ 固定 7 章节输出+降级  │
                                           └─────────────────────┘
```

### 4.2 数据流
```
账号URL/关键词 → [M1] flat 列目录(快) → 逐条全量元数据(带限流) → 原始 CSV
→ [M3] 统计(均值→爆款筛选→多维分布) → stats.md + 爆款子集 CSV
→ [M4] 统计摘要+爆款样本喂给 LLM → 拆解报告 report.md
```

### 4.3 技术选型
| 组件 | 选择 | 理由 |
|---|---|---|
| 采集引擎 | yt-dlp(Python 库调用,非命令行子进程) | 可编程拿到结构化字典,免解析文本 |
| 数据处理 | pandas | 统计/分组/导出方便 |
| 中文分词 | jieba | 标题高频词统计需要 |
| LLM 调用 | openai SDK(OpenAI 兼容协议) | 一套代码通吃 DeepSeek / Kimi / OpenAI 等 |
| 界面 | argparse CLI | 需求指定,最快落地 |

## 5. 功能模块设计

### M1 采集模块 `collector.py`

**两阶段采集**(核心工程决策,兼顾速度与数据完整度):
1. **列目录阶段**:`extract_flat` 模式快速拿视频 ID 列表(一个请求拿全列表,不逐条访问)
2. **全量阶段**:逐条抓完整元数据,每条之间 `sleep(随机区间)` 限流

**入口**:
- 频道模式:URL 自动识别平台(`space.bilibili.com` → B站;`youtube.com/@xx` → YouTube)
- 搜索模式:B站用 yt-dlp 内置 `bilisearch{N}:关键词`,YouTube 用 `ytsearch{N}:关键词`

**字段补抓**:yt-dlp 不返回 B站收藏数 → 对 B站视频额外调一次官方公开 API `api.bilibili.com/x/web-interface/view?bvid=xx` 补齐收藏数(这是你的核心 KPI,必须有);YouTube 无公开收藏数,留空。

**限流策略**:
| 平台 | 逐条间隔(默认,可配) | 附加 |
|---|---|---|
| B站 | 2–4 秒随机 | 请求级 sleep 1s |
| YouTube | 3–6 秒随机 | 建议配代理 `--proxy` / cookies |

支持 `--cookies chrome`(读取浏览器登录态,提升 YouTube 成功率);单条失败跳过并计数,不中断整批。

### M2 数据层(CSV Schema)

文件:`output/raw/{日期}_{平台}_{来源slug}_raw.csv`,编码 **utf-8-sig**(Excel 直开中文不乱码)。

| 字段 | 类型 | 说明 |
|---|---|---|
| platform | str | bilibili / youtube |
| channel | str | 频道名 |
| video_id | str | BV号 / YouTube ID |
| url | str | 视频链接 |
| title | str | 标题 |
| description | str | 简介(截断 500 字) |
| tags | str | 标签,`\|` 分隔 |
| upload_time | str | 发布时间 ISO(北京时间) |
| duration_sec | int | 时长秒 |
| views | int | 播放 |
| likes | int | 点赞 |
| favorites | int | 收藏(B站补抓;YouTube 空) |
| comments | int | 评论数 |
| collected_at | str | 采集时间 |

### M3 统计分析模块 `analyzer.py`

**爆款判定规则**(需求 2 的落地):
- 频道模式:爆款 = 播放 ≥ `3 × 该账号历史均值`(倍数 `--viral-mult` 可调)
- 搜索模式:以**搜索结果集均值**为基准(同一逻辑,基准换掉)
- 同时输出中位数 / P90 作参考,防止被头部极端值拉偏

**统计维度**:
| 维度 | 内容 |
|---|---|
| 发布时段 | 0-6/6-9/9-12/12-14/14-18/18-21/21-24 七档(北京时间)+ 星期分布。注:YouTube 公开数据通常只有日期无小时 → 无小时数据时自动跳过时段分析并注明 |
| 标题特征 | 长度分布、疑问句占比、`?!【】` 标点使用率、jieba 高频词 TOP20、思辨钩子词专项统计(为什么/凭什么/如果/你会/难道) |
| 时长分布 | <15s / 15-30s / 30-60s / 1-3min / >3min |
| 互动效率 | 点赞率、**收藏率**(核心 KPI)、评论率(均 ÷ 播放) |

**产出**:`stats.md`(全维度统计报告)+ `viral.csv`(爆款子集,含 `is_viral` 标记)。

### M4 LLM 拆解报告模块 `report.py`

- 输入:统计摘要 + 爆款 TOP N(默认 15 条:标题/时长/播放/点赞/收藏/发布时间/链接)
- 协议:OpenAI 兼容,环境变量 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`(默认建议 DeepSeek,成本最低)
- Prompt 内置赛道上下文:青年思辨哲学 / 18–23 岁男性 / 目标高收藏
- **输出固定 7 章节**(需求 3 原样落地):
  1. 发布时间推荐
  2. 标题模板(8–10 个可直接套用)
  3. 钩子模板(前 3 秒开口,6–8 个)
  4. 脚本节奏(开头/中段/结尾结构)
  5. 标签策略
  6. 选题方向(10 个具体选题)
  7. 避坑清单(5–8 条)
- 约束:prompt 明令"只引用给定数据,禁止编造数字"
- **降级策略**:未配 API Key 时不报错,输出统计版报告骨架(数据部分完整,AI 解读部分留占位)

### M5 配置与 CLI `main.py` + `config.py`

```
py main.py collect --mode channel --url <B站空间/YouTube频道> [--limit 60] [--analyze] [--report]
py main.py collect --mode search --keyword "哲学 思辨" --platform bilibili [--limit 50] [--analyze] [--report]
py main.py analyze --csv output/raw/xxx.csv [--viral-mult 3]
py main.py report --csv output/raw/xxx.csv [--top 15] [--model deepseek-chat]
```
公共参数:`--proxy` / `--cookies <浏览器名>` / `--delay-min` / `--delay-max` / `--out-dir`

`--analyze` / `--report` 挂在 collect 上 = 采完自动出报告,一条命令跑完全链路。

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 反爬 | 全部请求带随机延时;默认参数下连续采集 50 条不触发平台风控 |
| 容错 | 单视频失败跳过(记录失败数);平台风控/网络中断 → 已采数据先落盘再退出,不丢 |
| 编码 | CSV 一律 utf-8-sig |
| 时区 | 统一北京时间分析 |
| 可复现 | 同一命令任何人可重跑;环境只有 requirements.txt 四个依赖 |

## 8. 验收标准

1. 给定 B站空间 URL → 产出 raw.csv,标题/播放/点赞/发布时间字段完整率 100%,收藏数完整率 ≥95%
2. `analyze` 对样例 CSV 的爆款筛选结果 = 人工按公式计算结果(提供合成数据自测)
3. stats.md 包含:时段表、高频词表、时长分布表、收藏率排名
4. 未配 API Key 时 `report` 输出降级报告,不抛异常
5. CSV 用 Excel 打开中文不乱码
6. YouTube 频道采集在配代理前提下可跑通(无代理时给出明确报错提示)

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| YouTube 数据中心 IP 风控 | `--proxy` 直通参数 + cookies 支持;README 给配置示例 |
| B站收藏数 API 变更 | 补抓失败时字段留空,统计自动降级跳过,不影响主流程 |
| LLM 幻觉数字 | prompt 硬约束"只引用给定数据";报告尾注数据截止时间 |
| 搜索模式爆款基准失真(结果集本身都是爆款) | 报告中同时给出绝对值分布,不只依赖倍数筛选 |
