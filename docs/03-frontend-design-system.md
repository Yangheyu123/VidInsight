# VidInsight 前端设计与交互规范

## 1. 设计方向

界面参考 ChatGPT 的安静专注、Notion 的内容层级和 Vercel 的技术质感，但不直接复制任何品牌。目标是“低噪声的数据工作台”：清晰、克制、可靠，数据本身始终是主角。

### 1.1 设计关键词

- 中性：黑、白、灰为主，品牌色只用于关键动作和状态。
- 留白：通过间距和排版建立层级，避免堆砌边框与彩色卡片。
- 精确：数字对齐、口径清楚、状态与数据来源可追踪。
- 轻量：小圆角、细边框、低阴影，不使用厚重渐变和拟物效果。
- 平静：动画短而有目的；错误明确但不制造视觉焦虑。

### 1.2 明确避免

- 大面积高饱和渐变、玻璃拟态、霓虹发光；
- 每张指标卡使用不同颜色；
- 过度圆角、厚阴影、悬浮卡片套卡片；
- 无意义插画、旋转 Loader、跳动数字；
- 只靠红绿表达涨跌；
- 传统后台式的拥挤工具栏和满屏分割线。

## 2. 技术实现约束

- React 18 + TypeScript + Vite。
- Tailwind CSS 4 管理原子样式和 Design Token。
- shadcn/ui 作为基础组件源码，Radix 原语负责可访问交互。
- TanStack Query 管理服务端状态；URL Search Params 管理可分享筛选状态。
- Recharts 绘制业务图表；图表必须封装主题与格式化层。
- React Router 6 管理路由与页面级错误边界。
- 不引入第二套全量 UI 组件库。

## 3. 视觉令牌

令牌使用语义名，组件不得散落硬编码色值。推荐用 OKLCH 定义，并同时维护亮色与暗色主题。

### 3.1 颜色

| Token | 亮色建议 | 用途 |
|---|---|---|
| `--background` | `#FFFFFF` | 页面背景 |
| `--foreground` | `#18181B` | 主文字 |
| `--surface` | `#FAFAFA` | 侧栏、次级区域 |
| `--card` | `#FFFFFF` | 卡片、弹层 |
| `--muted` | `#F4F4F5` | Hover、Skeleton、标签背景 |
| `--muted-foreground` | `#71717A` | 次级文字 |
| `--border` | `#E4E4E7` | 细边框 |
| `--primary` | `#18181B` | 主按钮与当前态 |
| `--accent` | `#2563EB` | 链接、图表焦点、可交互强调 |
| `--success` | `#16803C` | 成功状态 |
| `--warning` | `#A15C00` | 警告状态 |
| `--destructive` | `#C93333` | 危险操作与失败 |

暗色主题以接近黑的 `#0A0A0A` 为背景、`#18181B` 为卡片、`#27272A` 为边框。避免纯黑大面积与纯白正文造成眩光。

数据图表使用固定且色盲友好的序列：蓝、紫、青、橙、玫红。涨跌除颜色外必须带 `↑` / `↓`、正负号或文字标签。

### 3.2 字体与数字

```css
--font-sans: "Geist", "Inter", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "Geist Mono", "SFMono-Regular", Consolas, monospace;
```

| 样式 | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| Display | 32 / 40 | 600 | 仅空状态或欢迎页 |
| H1 | 24 / 32 | 600 | 页面标题 |
| H2 | 18 / 28 | 600 | 页面区块标题 |
| H3 | 15 / 24 | 600 | 卡片标题 |
| Body | 14 / 22 | 400 | 正文、表格 |
| Small | 12 / 18 | 400/500 | 辅助信息、标签 |

指标数字使用 `font-variant-numeric: tabular-nums`。中文正文不使用全局超宽字间距；英文大写标签可使用轻微 tracking。

### 3.3 间距、圆角与阴影

- 4px 基础网格；常用间距 4、8、12、16、20、24、32、40、48。
- 控件高度：紧凑 32px、默认 36px、大按钮 40px。
- 圆角：输入框/按钮 6px，卡片 8px，弹窗 12px，圆形头像除外。
- 卡片默认只有 `1px` 边框，无阴影；浮层使用柔和双层阴影。
- 内容区最大宽度 1600px，左右内边距桌面 32px、窄屏 20px。

## 4. 应用框架

```text
┌──────────────┬─────────────────────────────────────────────────┐
│ Logo / 空间   │ 页面标题与面包屑                 搜索  帮助  用户 │ 56
├──────────────┼─────────────────────────────────────────────────┤
│ 总览          │ 页面说明                         时间范围 / 操作 │
│ 账号          │ ─────────────────────────────────────────────── │
│ 内容          │                                                 │
│ 对比分析      │                页面内容                          │
│              │                                                 │
│ 数据管理      │                                                 │
│ 设置          │                                                 │
│              │                                                 │
│ 系统状态      │                                                 │
└──────────────┴─────────────────────────────────────────────────┘
     240px                         fluid
```

- 侧栏宽 240px，可折叠为 64px；当前项使用浅灰背景和清晰文字，不使用厚重色块。
- 顶栏高 56px，采用轻微透明和 `backdrop-blur`，滚动时保留底边框。
- 主内容区保持单一滚动容器，页面标题区与内容间距 24px。
- 1024-1279px 默认折叠侧栏；小于 1024px 使用 Drawer，表格允许横向滚动。

## 5. 核心页面

### 5.1 总览 `/`

```text
总览                          日 / 周 / 月   账号 ▾   刷新   导出
所有账号的关键表现       最后同步 2 分钟前 · 官方 API

账号数        总播放量       总点赞数       互动率
12            1,284.6 万     84.2 万        7.4%
+1 本周期      ↑ 12.4%        ↑ 8.1%         ↓ 0.3pp

┌────────────────────────────┬─────────────────────┐
│ 表现趋势                    │ 账号表现             │
│ 播放 / 点赞 / 评论  [切换]   │ 横向条形或简洁排行    │
└────────────────────────────┴─────────────────────┘

热门视频                                      查看全部 →
简洁表格：视频 / 账号 / 发布时间 / 播放 / 互动率 / 趋势
```

- 指标卡为同一中性色调，变化值放在数字下方；异常或估算才使用状态色。
- 趋势图默认只突出一条主序列，其余序列可切换，减少视觉拥挤。
- 所有卡片标题旁提供口径 Tooltip；更新时间与来源放在标题区域。
- 周期切换使用紧凑 Segmented Control，支持日/周/月和自定义日期；切换后 KPI、趋势、排行和视频明细使用同一筛选对象。
- “导出”生成继承当前周期、账号、搜索与排序的 XLSX；异步任务创建后在 Toast 和导出中心均可追踪。

### 5.2 账号列表 `/accounts`

- 顶部：搜索、授权状态筛选、排序、“批量录入”次按钮和“连接账号”主按钮。
- 每行展示头像、昵称、授权状态、粉丝、视频、最近同步、下次同步和更多菜单。
- 授权异常使用浅色状态 Badge，并在行内给出“重新授权”动作。
- “手动同步”创建任务后显示 Toast，并将该行同步状态实时更新。
- 行菜单提供启用/停用；删除仅 admin 可见并使用 AlertDialog 明确“停止任务、撤销凭证、保留历史”的影响。
- 批量录入使用可粘贴表格或 CSV/XLSX，逐行显示成功/失败，不因单行重复回滚其他账号。

### 5.3 视频列表 `/videos`

- 筛选器分两层：常用条件常驻，高级筛选放 Popover。
- 搜索和筛选写入 URL；返回页面恢复原位置与条件。
- 选中行后出现贴近表格的批量操作条，不长期占据页面空间。
- 缩略图比例 9:16，显示为 36×48；加载失败使用中性占位。
- 数值列右对齐，标题列固定最小宽度，表头支持服务端排序。

### 5.4 视频详情 `/videos/:id`

- 左上是封面、标题、账号与发布时间；右上是分析、导出、更多操作。
- 第一屏展示 4 个核心指标和生命周期趋势。
- 内容区域使用页内 Tabs：`表现`、`内容分析`、`评论洞察`、`原始信息`。
- AI 结论采用“结论—证据—建议”结构，置信度和模型版本作为次级信息。
- 深度指标旁固定展示 `官方`、`Computer Use`、`导入`、`合作数据`、`受控爬虫`、`自有埋点` 或 `模型估算` 来源徽标；缺失显示 `—`，不以 0 替代。

### 5.5 内容分析 `/analysis`

- 顶部提供分析覆盖率、待分析数、失败数和本月成本。
- 主体是可筛选的分析结果，不以聊天框作为唯一入口。
- 运营建议可使用右侧 AI 助手抽屉：回答必须引用平台内的视频、指标或评论证据，支持跳转原始对象。
- 生成操作显示预计成本与数据范围，并需要显式确认批量任务。

### 5.6 任务与导入

- 任务页采用紧凑表格；状态、进度、开始/结束时间、重试次数和错误可展开查看。
- 导入使用四步 Stepper：上传 → 映射 → 预检 → 确认。
- 错误信息按“可修复原因 + 行号 + 字段 + 原值”展示，允许下载错误报告。

### 5.7 诊断中心 `/diagnoses`

- 顶部按账号、日/周/月、规则码、严重度和数据质量筛选，筛选同步到 URL。
- 列表每项遵循“结论 → 证据 → 参考建议”，显示命中指标、基线/阈值、来源、质量和生成时间。
- 五类 MVP 规则使用稳定中文标题；缺少完播率或视频级涨粉归因时展示“数据不足”，不显示看似确定的优化结论。
- 建议固定显示“基于相关性数据，仅供运营参考”；LLM 润色失败时仍展示规则模板。
- 可跳转视频详情、重新诊断或按当前筛选导出，不提供自动发布或自动改写脚本入口。

### 5.8 数据源连接器 `/settings/connectors`

- 仅 admin 可访问；列表显示来源类型、允许字段、审批状态、到期时间、健康度、最近抽检和熔断状态。
- 创建受控连接器采用 Stepper：范围 → 策略 → 审批 → dry-run → 抽样确认 → 启用。
- 页面不展示 Cookie、Token、完整 DOM 或浏览器 profile；危险操作要求确认并写审计。
- 挑战页、结构漂移或 Policy Gate 拒绝使用明确红/琥珀状态，不提供“绕过”“换 IP 重试”等动作。

## 6. 组件规范

### 6.1 Button

- `default`：每个视区通常仅一个主动作；深色实心。
- `secondary`：浅灰背景，用于次要动作。
- `outline`：边框按钮，用于筛选和中性操作。
- `ghost`：表格与工具栏中的低强调动作。
- `destructive`：只用于不可逆或高影响操作。
- 图标按钮必须有 `aria-label` 和 Tooltip。

### 6.2 Card

Card 不是默认布局单位。只有内容具备独立语义、边界或交互时才使用卡片；普通章节以标题、间距和细分隔线组织。禁止多层 Card 嵌套。

### 6.3 Table

- 表头高 40px、数据行 48-56px；Hover 使用 `muted` 背景。
- 首列选择框、主体列、数值列和操作列具有稳定位置。
- 空值显示 `—`，绝不混用 `0`、空字符串和 `N/A`。
- 行内菜单不隐藏核心高频操作；危险操作始终二次确认。
- Loading 使用保持列宽的 Skeleton 行，避免页面跳动。

### 6.4 Filter bar

- 已生效条件使用可关闭 Chip，并提供“清除全部”。
- 时间范围和账号是跨页面最重要的筛选，位置保持一致。
- 筛选变化在短延迟后自动请求；文本搜索使用 300ms 防抖。

### 6.5 Status badge

Badge 采用浅背景、深文字和小状态点。词汇统一：正常、即将到期、已过期、已暂停、处理中、部分完成、失败。不要同义词混用。

### 6.6 Toast 与错误

- 成功 Toast 简短、3 秒自动关闭；失败 Toast 不自动消失或提供“查看详情”。
- 页面级错误包含原因、重试和支持用的请求 ID。
- 表单错误紧邻字段；服务端字段错误映射回对应控件。
- 不用 Toast 代替不可逆操作确认。

## 7. 图表规范

- 图表区域最小高度 280px；标题、口径和来源在图表外部。
- X 轴控制刻度数量，Y 轴从 0 开始，除非截断能显著提升阅读且明确标识。
- Tooltip 显示完整时间、精确值、单位、来源和环比；数值右对齐。
- 不使用 3D、环形装饰、面积渐变堆叠或超过 5 个同时可见序列。
- 饼图仅适合 5 类以内的构成；趋势使用折线，比较使用条形，转化使用漏斗前需确认业务顺序。
- 空数据、部分数据和采集中是不同状态，不能用一条平线混淆。

## 8. 加载、空状态与反馈

| 状态 | 表现 |
|---|---|
| 首次加载 | 页面骨架与真实布局一致 |
| 后台刷新 | 保留旧数据，在更新时间旁显示轻量旋转标识 |
| 无账号 | 解释价值并提供“连接账号”主动作 |
| 无筛选结果 | 保留筛选器，建议清除或调整条件 |
| 数据延迟 | 黄色非阻塞提示，说明最后成功时间与影响 |
| 权限不足 | 说明需要的角色，不展示无意义重试 |
| 局部失败 | 保留可用区域，只在失败组件内提供重试 |

## 9. 动效

- Hover 与颜色过渡 120-160ms；抽屉/弹窗 180-220ms。
- 使用 `ease-out` 进入、`ease-in` 离开。
- 尊重 `prefers-reduced-motion`，禁用非必要位移动画。
- 数字更新不做老虎机式滚动；图表首载可轻微淡入，筛选更新不重复大动画。

## 10. 可访问性与响应式

- 正文与背景对比度至少 4.5:1，大字与 UI 图形至少 3:1。
- 焦点环清晰可见，键盘顺序与视觉顺序一致。
- Dialog 打开后锁定焦点，关闭后回到触发器；Escape 可关闭非强制弹层。
- 表格使用语义表头；排序状态通过 `aria-sort` 表达。
- 图表提供文本摘要或可访问数据表。
- 桌面为主；小于 768px 允许查看关键指标与任务状态，但复杂分析建议提示使用桌面。

## 11. 推荐前端目录

```text
frontend/src/
├─ app/                    # Router、Provider、全局错误边界
├─ components/
│  ├─ ui/                  # shadcn 基础组件
│  ├─ charts/              # 统一图表容器、主题、Tooltip
│  └─ shared/              # DataTable、PageHeader、EmptyState
├─ features/
│  ├─ auth/
│  ├─ dashboard/
│  ├─ accounts/
│  ├─ videos/
│  ├─ analysis/
│  ├─ imports/
│  └─ jobs/
├─ lib/                    # API client、formatters、query client
├─ routes/                 # 页面路由模块
├─ styles/                 # tokens 与全局样式
└─ types/                  # 生成类型的补充类型
```

功能目录内部按 `api.ts`、`queries.ts`、`components/`、`schemas.ts` 和 `routes/` 组织。OpenAPI 生成类型不得手工复制维护。

## 12. 视觉验收清单

- 页面使用统一的 4px 网格、控件高度、圆角和边框。
- 首屏只有一个明确主行动，不出现彩色卡片拼盘。
- 表格数字对齐，空值、单位、精确值与紧凑值表现一致。
- 每个业务指标都能找到口径、时间范围、更新时间和数据来源。
- Loading、空、错误、部分成功、权限不足与过期状态均有设计。
- 亮色/暗色、键盘导航、缩放 200% 和 1024px 宽度通过验收。
