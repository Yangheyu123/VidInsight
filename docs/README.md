# VidInsight 开发文档索引

## 1. 文档目的

本目录是 VidInsight 的统一开发基线，面向产品、设计、前端、后端、数据、算法、测试和运维角色。出现冲突时，遵循以下优先级：

1. 已确认的变更记录或 ADR；
2. `技术栈选型最终方案.md`；
3. 本目录中的开发文档；
4. `AI短视频数据看台平台技术方案.md` 与 `抖音看台调研文档.md`。

旧文档中的 `Spring Boot + Vue3/Element Plus` 属于历史方案。实现统一采用 `FastAPI + React`。

## 3. 已统一的关键决策

| 决策 | 结论 | 原因 |
|---|---|---|
| Web 技术栈 | React + TypeScript + Vite | 与最终选型一致，适合现代 SaaS 界面 |
| UI | Tailwind CSS 4 + shadcn/ui | 保留组件源码控制权，便于形成克制统一的设计系统 |
| API 服务 | FastAPI 单体模块化起步 | 开发快、异步友好、与 AI 生态一致 |
| 主库 | PostgreSQL 16 | MVP 数据规模足够，降低多存储运维成本 |
| 异步任务 | Celery + Redis | 支持采集、分析、重试与定时任务 |
| 分析库 | MVP 不引入 ClickHouse | 达到查询或容量门槛后再演进 |
| 数据源 | 官方 API → Computer Use → 授权导入/合作数据 → 受控爬虫 | 逐级补充缺失字段，每个值保留来源与质量等级 |
| Computer Use | 受控补充、默认关闭 | 只处理官方 API 缺失且自有账号后台可见的数据 |
| 受控爬虫 | 字段级最后兜底、默认关闭 | 仅在前述来源都不可用且授权、访问政策与合规审批允许时启用 |
| BI 工具 | 不作为主产品 UI | 主业务体验由 React 实现；Grafana 只做系统监控 |
| API 版本 | `/api/v1` | 为后续兼容演进保留空间 |
| 时间与数值 | 数据库存 UTC，界面默认 Asia/Shanghai；计数用 BIGINT | 避免跨时区和溢出问题 |

## 4. 待业务确认项

这些事项不阻塞基础开发，但必须在相应功能进入开发前确认：

- 抖音开放平台实际获批的 Scope、配额、字段和回调规则；
- 收藏数、完播率、平均播放时长等深度指标的合法来源；
- 首批租户是单团队还是多企业；文档的数据模型按多工作区预留隔离能力；
- 是否允许调用境外大模型，以及可发送的数据范围；
- 爆款阈值是否固定为 10 万播放，还是按账号基线动态计算；
- 评论原文的合同保留期取 90 天还是 180 天。
- 若启用 Computer Use 或受控爬虫，需确认允许的账号、域名、页面、字段、频率、审批编号、责任人和 Kill Switch。

## 5. 文档维护规则

- 需求变化必须同步更新产品需求、API、数据模型和验收标准中受影响的部分。
- 新增重大技术决策时，在 PR 描述中记录背景、选择、替代方案和影响。
- API 以 FastAPI 生成的 OpenAPI 为机器可读真相，本目录描述业务语义与稳定约定。
- 所有日期使用 `YYYY-MM-DD`，接口时间使用 ISO 8601 UTC，例如 `2026-08-05T08:00:00Z`。
- 根目录 `完整开发文档.md` 是早期单文件汇总版；后续研发、评审与变更以本目录的拆分文档集为准。
